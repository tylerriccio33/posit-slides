What “easiest” actually means

(VERBATIM) My thesis called for optimizing for the “easiest” migration options. This is what I mean.

Easiest means: productive on day one

  • Early wins

  • The thin-slice effect

(VERBATIM): Can the Data Scientist be productive immediately?

[click] Early wins — real code that runs on day one, before anyone has mastered environments, classes, or types.

Impresses superiors; feels good to accomplish things.

[click] Thin-slice theory, a well established psychological phenomenom: First impressions aren’t accurate, but they have more predictive power and persistence than we’d like. We’re judgemental animals.

Callback: my first ten minutes installing Python was that thin slice. Everyone has had that, and it’s not limited to programming, obviously.

Not fair, but real, and it has to be managed.

dplyr

df |>
  filter(status == "paid") |>
  select(
    is_customer = str_like(persona, 'cust'), 
    revenue = sum(c_across(rev1:rev8), na.rm = TRUE)
  )

Polars

df.filter(pl.col("status") == "paid").select(
    is_customer = pl.col('persona').str.contains('cust'), 
    revenue = pl.sum_horizontal(cs.starts_with('rev'))
    )

Easiest = it works in ten minutes.

[click] dplyr — the room should recognize it instantly. Don’t explain.

[click] Polars — the pipe became a dot. filter is filter, select is select. That is the entire lesson for day one.

[click] Say it as a property of the CHOICE, not of Polars: “This is what the easy option looks like on day one — it works in ten minutes. Whatever you’re migrating to, this is the test.”

Day one decides whether people keep going.

Not all APIs are created equal — some are thin wrappers exposing every private method. A user-friendly framework pays off while people are still coming up to speed on everything else.

The goal is comfort, not full control of a complex system.

Easiest means: the same shape of thought

  • Easy syntax is a virtue
  • Import your philosophy

Verbal signpost: “That’s day one. The second thing easiest means is about every day after: the Data Scientist doesn’t have to relearn how to think about data.”

[click] Easy syntax — other options leaned on verbose, heavily-typed languages that added friction before anyone got to the actual work.

[click] Import your philosophy — Polars’ expression API preserves the dplyr way of thinking about data, not just its syntax. select, transform, filter, aggregate — no detour through OOP, strong typing, or imperative loops.

Same thought, different language

sum(revenue[status == "paid"]) becomes:

pl.col("revenue")
  .filter(pl.col("status") == "paid")
  .sum()

Easiest = the same sentence, in a new language.

This is transfer, not onboarding: once you know the syntax, does the system let you keep thinking about data the way you already do?

Subset a vector by a condition, then reduce it. Same thought. The R version is a bracket; the Polars version is a chain — but it’s the same sentence.

[click] Nobody wrote a for loop. The vectorized mental model came with us. That’s the property to look for: the option where your old sentences still parse. Not “Polars is great” — “this is what easy looks like.”

Same thought, every column

dplyr

df |>
  mutate(across(
    starts_with("rev"),
    \(x) x * 1.1
  ))

Polars

import polars.selectors as cs

df.with_columns(
  cs.starts_with("rev") * 1.1
)

Easiest = you didn’t learn a new way to think.

[click] dplyr — pick columns by a rule, apply one expression to all.

[click] Polars — same idea. cs is Polars’ column selectors.

[click] Same idea, both sides. The chain is the pipe; the expression is the thing inside across. Again — the point isn’t that Polars has selectors; it’s that the easy option is the one where the Data Scientist didn’t have to learn a new way to think.

Morale beat lives here: when everyone writes it this way, code is readable and reviewable across the team. Shared idioms mean the whole team has the same migration, not eight different ones.

Some days, you don’t need to learn anything new.

Migrating is already information overload — it doesn’t all have to land on day one. You don’t take Calc 4 before Calc 1.

Once people are comfortable, they move on to the fancier stuff on their own, and make better-informed decisions about it.

Productivity

→ Familiarity

→ Confidence

Verbal signpost: “Put the two pillars together.”

[click] Productivity — day one works. [click] Familiarity — the shape of thought carries over. [click] Confidence — and confidence is the thing a migration actually runs on. Morale isn’t a separate goal; it’s what you get when the first two are true.
